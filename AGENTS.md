# Agent guidance for nquake-reborn

The canonical source of truth for AI coding agents in this repo. `CLAUDE.md`
is a symlink to this file.

## What this is

A **web installer for nQuake**, the QuakeWorld package: a Vite + Preact +
Tailwind single-page app that downloads the game files into a folder the
user picks, plus a thin Tauri desktop shell under `tauri/` that embeds the
compiled page. It replaces the NSIS installer in `nQuake/client-win32` and
the bash installers in `nQuake/client-linux` / `nQuake/server-linux`.

Two things shape every design decision here:

1. **GitHub release assets have no CORS.** A browser cannot fetch the
   distfiles zips. So the installer reads `manifest.json` from
   `nQuake/distfiles` (generated by that repo's `scripts/build-manifest.mjs`)
   and fetches every file individually from `raw.githubusercontent.com`. The
   newest ezQuake / MVDSV / KTX come from the `upstream-mirror` branch of
   this repo, kept fresh by `.github/workflows/mirror-upstream.yml`. There
   are no zips anywhere; don't introduce an unzip step.
2. **Writing files goes through one seam.** `src/platform/destination.ts`
   is the interface; `fs-access.ts` (browser), `tauri.ts` (desktop) and
   `mock.ts` (simulation) implement it. A new surface is a new
   implementation, never a branch in the installer.

## Build and test

```sh
npm ci
make dev / build / preview / test / lint / fmt / fmt-check
node scripts/screenshots.mjs        # every step, desktop + phone, dark + light
make bump / make changelog VERSION= # release tooling (read-only / scratch)
```

Run `make fmt` before committing; `fmt-check` is its own CI gate.

## Layout and boundaries

| Layer          | Holds                                                                                  | May import           |
| -------------- | -------------------------------------------------------------------------------------- | -------------------- |
| `src/domain`   | `options.ts` (what the wizard asks), `plan.ts` (answers → files), `configs.ts` (generated cfg/scripts), `manifest.ts` / `upstream.ts` (catalog shapes), `install-state.ts`, `readme.ts`, `format.ts`, `progress.ts` | nothing outside domain |
| `src/net`      | `sources.ts` (URLs, catalog loading), `transport.ts` (fetch + retry), `installer.ts` (runs a plan) | domain, platform types |
| `src/platform` | `capabilities.ts` (which surface, can it install), `destination.ts`, the three destinations | domain |
| `src/ui`       | `primitives.tsx`, `Stepper.tsx`, `icons.tsx`, `steps/*`                                | domain, app types    |
| `src/app`      | `wizard.ts` (state + flow), `App.tsx` (shell), `main.tsx`, `theme.ts`                  | everything           |

`src/domain/` is pure and eslint keeps it that way (no DOM, no fetch, no
imports from the layers above). **Put every decision there**: which files
a choice adds, what a config says, what counts as "unchanged". The UI edits
`InstallOptions`; the installer walks the `InstallPlan`; neither re-derives.

The wizard's steps are computed from the options and the **mode**
(`stepsFor` in `app/wizard.ts`). **Simple** (the default) is Next, Next,
Next on the defaults in `domain/options.ts` — QuakeWorld's standard ports
(27500 / 28000 / 30000), the newest ezQuake and MVDSV+KTX, 24-bit textures,
WASD, the full map pack — welcome → target → folder → review → install →
done. **Advanced** unfolds client → config and/or server between target
and folder. The switch sits in the card header; `?mode=` presets it. Keep
the defaults sound: a Simple install must never need the Advanced steps to
be playable. Each step is a component taking `ctx: WizardCtx`.

## The wrapper is thin

`tauri/` embeds `dist/` and holds only what a webview can't do: pick a
folder, write in it, reveal it (three official plugins, configured in
`tauri/src-tauri/capabilities/default.json`) and one Rust command,
`set_executable`, because a webview cannot chmod. It imports nothing from
`src/`. Anything else a desktop feature seems to need goes in `src/` behind
the destination seam. Wanting a second Rust file is the signal to stop and
re-ask. Touch `tauri/` → re-read `tauri/README.md`.

## Simulation mode

`platform/capabilities.ts` decides. Phones, browsers without
`showDirectoryPicker`, non-HTTPS pages and `?mock=1` all get the full wizard
with a simulated folder and simulated downloads (`platform/mock.ts`), and say
so in a banner. Keep the mock path identical to the real one apart from the
`Destination` and `Transport` — that is what makes the screenshot harness
representative.

## Screenshots

`scripts/screenshots.mjs` drives the wizard through its `data-testid` hooks
with `?mock=1` and writes `screenshots/<scenario>/<viewport>-<theme>/<nn>-<step>.png`
for simple / client / server / both at desktop (1440×900) and phone
(390×844), dark and light (`simple` is the default mode; the other three
switch to Advanced on the target step). Run it after any visible change and look at the PNGs; keep the
`data-testid` attributes it clicks (`nav-next`, `target-*`, `platform-*`,
`mode-*`, `opt-*`, `nickname`, `hostname`, `pick-folder`, `install-percent`,
`done`).
Playwright is resolved from a global install, not a project dependency.

## Design

Familiar to nquake.com: charcoal linen background, the "nQuake" wordmark
with an orange *n* and silver *Quake* in Open Sans Condensed, the Playball
slogan, yellow links, an orange primary button. Tokens live in
`src/styles/theme.css` (dark default, light variant); use the slot names
(`bg-surface`, `text-muted`, `border-line`, `text-accent`…), never raw
colours in components. Desktop shows a sidebar stepper; phones get a compact
strip and a sticky bottom nav. Both are primary.

## Releases and changelog

Mirrors the notes app. A user-visible PR drops a fragment in
`.changes/unreleased/<unix-ts>-<slug>.md` (`type: Added|Changed|Fixed|
Removed|Security|Deprecated`, optional `title:`, optional `breaking: true`,
one-sentence body); the `changeset` CI job enforces it (skip-list in
`scripts/release/check-changeset.mjs`, or the `no-changelog` label).
`release.yml` is dispatched by hand, derives the bump from the fragments
(`scripts/release/compute-bump.mjs`), collates `CHANGELOG.md`, bumps
`package.json`, tags `vX.Y.Z`, creates a draft GitHub Release, builds the
Tauri bundles for Windows / macOS (Intel + Apple Silicon) / Linux with
`tauri-action`, attaches them, publishes, and chains into `pages.yml`.

`pages.yml` assembles the root slot (latest `v*` tag), `/preview/` (`main`)
and an opt-in `/branch/` into one artifact. The base path is
`/<repo-name>/` on `*.github.io` and `/` when the `PAGES_CNAME` secret is
set; `vite.config.ts` reads it from `VITE_BASE`. The repository's Pages
source must be set to **GitHub Actions** once by hand.
