# Agent guidance for nquake-reborn

The canonical source of truth for AI coding agents in this repo. `CLAUDE.md`
and `.github/copilot-instructions.md` are symlinks to this file.

## What nQuake is

**QuakeWorld** is the multiplayer version of id Software's Quake (1996):
client-side prediction, 77 fps physics, and a competitive scene that never
stopped. It is still played on public servers today, mostly through the
**ezQuake** client and the **MVDSV** server running the **KTX** mod.

**nQuake** is the QuakeWorld package for newcomers, started by Empezar in
2007. Its own FAQ puts it best: *"nQuake is a package that includes everything
you need to play QuakeWorld. This includes a client (ezQuake), custom maps,
models, textures and other things that makes it easier to get started. If you
were to download ezQuake individually, you would have to spend several hours
downloading extras before you were able to have anything resembling a modern
game."* It ships the shareware game data (`pak0.pak`), ezQuake, replacement
models and 24-bit textures, hundreds of maps, a tuned default config with
aliases and binds, and — for the server flavour, **nQuakesv** — MVDSV + KTX
with QTV (spectating/demos) and QWFWD (a proxy), configured and startable.

Historically nQuake was an NSIS `.exe` (`nQuake/client-win32`) and bash
scripts (`nQuake/client-linux`, `nQuake/server-linux`) that downloaded
`<package>.zip` files from mirrors and unzipped them. **This repository is the
rewrite: the same job done from a web page**, plus a thin desktop shell. It
is live at **https://nquake.com/nquake-reborn/** (the nQuake GitHub org has a
Pages custom domain; the Pages URL redirects there).

### QuakeWorld vocabulary you will meet in the code

| Term | Meaning |
| --- | --- |
| `id1/` | The base game directory. `pak0.pak` (shareware, redistributable) and `pak1.pak` (registered — the user must own Quake; the installer never downloads it, only copies the user's). |
| `qw/` | QuakeWorld's game dir: nQuake's pk3s, `autoexec.cfg`, `nquake_default.cfg`, maps, skins, sounds. |
| `ezquake/` | The client's own dir: `ezquake.pk3`, `configs/` (user configs live here), `sb/` (server browser). |
| `.pak` / `.pk3` | id's archive format / a zip with a different extension. ezQuake reads both from `id1`, `qw`, `ezquake`. |
| ezQuake | The client. Releases at github.com/QW-Group/ezquake-source: `ezquake.exe`, `ezQuake-x86_64.AppImage`, `ezQuake.app`. |
| MVDSV | MultiView Demo SerVer, the server binary (`mvdsv`, `mvdsv.exe`). Runs one game per port; default port 27500. |
| KTX | Kombat Teams eXtreme, the server-side mod every public server runs (`ktx/qwprogs.so` / `.dll`). Game modes (1on1, 4on4, ffa, ctf, race…) are selected in-game. |
| QTV | Quake TV: a proxy that lets spectators watch and serves demos over HTTP. TCP 28000 by default. |
| QWFWD | A UDP forwarding proxy players route through for better connections. UDP 30000 by default. |
| KTX port config | `ktx/portN.cfg`, passed with `+exec`; the process is started as `mvdsv -port 27500 -game ktx +exec port1.cfg`. |
| `pwd.cfg` | rcon (remote console) and QTV passwords, exec'd by `server.cfg`. |
| CA / TF / FFA | Clan Arena (`cace/`), Team Fortress (`fortress/`), matchless free-for-all (`ffa/`) — addon mods, each its own `-game` and port. |

### The first-run config mechanism

`gpl/ezquake/configs/config.cfg` is nearly empty: it sets
`_nquake_first_startup 1`. `qw/autoexec.cfg` execs `configs/config.cfg`,
then, only when that flag is 1, `nquake_default.cfg` (the full nQuake config)
and `configs/preset.cfg`, then clears the flag. `cfg_save_onquit` saves the
merged result to `config.cfg` on exit. **`ezquake/configs/preset.cfg` is the
one file the installer writes for the user** (name, `m_pitch`, movement
binds) — `src/domain/configs.ts#renderPresetCfg`. An existing `config.cfg` is
backed up as `config-<timestamp>.cfg` before an update install, as the old
Windows installer did.

## The two facts that shape everything

1. **GitHub release assets have no CORS.** `github.com/…/releases/download/…`
   redirects to `release-assets.githubusercontent.com`, which sends no
   `Access-Control-Allow-Origin`; a browser `fetch` fails (verified in
   Chromium, this session). `raw.githubusercontent.com` sends `*`. So the
   installer reads `manifest.json` from `nQuake/distfiles` (every file with
   size + sha256, generated by that repo's `scripts/build-manifest.mjs` on
   each push) and downloads **each file individually** from raw, at the
   commit the manifest names. There are no zips and no unzip step anywhere;
   don't add one. Files must stay under raw's 100 MB limit (largest today:
   99 MB).
2. **Writing files goes through one seam.** `src/platform/destination.ts` is
   the interface; `fs-access.ts` (browser, File System Access API, Chromium
   desktop only), `tauri.ts` (desktop app, Tauri plugins) and `mock.ts`
   (simulation) implement it. A new surface is a new implementation, never a
   branch inside the installer.

The newest ezQuake / MVDSV / KTX come from this repo's **`upstream-mirror`
branch**: `.github/workflows/mirror-upstream.yml` (daily 04:17 UTC and
`workflow_dispatch`) runs `scripts/mirror-upstream.mjs`, which asks the
GitHub API for each project's latest release, downloads the assets, extracts
them and force-pushes an orphan branch with `upstream.json` + the files laid
out as they land in the install folder (`ezquake/windows-x64/ezquake.exe`,
`ktx/linux-amd64/ktx/qwprogs.so`, …). QTV and QWFWD publish no binaries and
stay bundled from distfiles (`sv-bin-x64` / `sv-bin-win32`). No macOS server
binaries exist anywhere. When `upstream.json` is missing or lacks a target,
the plan falls back to the bundled binaries and adds a note.

## Build and test

```sh
npm ci
make dev / build / preview / test / lint / fmt / fmt-check
node scripts/screenshots.mjs        # every step, 4 scenarios × desktop+phone × dark+light
make bump / make changelog VERSION= # release tooling (read-only / scratch)
```

Run `make fmt` before committing; `fmt-check` is its own CI gate. The test
suite is fast (vitest, ~40 tests) and covers the plan builder, the config
generators, the install record, the wizard step flow and the installer run
against a fake transport and destination.

Handy URL params for development: `?mock=1` (force simulation),
`?mode=simple|advanced`, `?platform=windows|linux|macos`, `?theme=dark|light`.
Build-time overrides `VITE_MANIFEST_URL` / `VITE_UPSTREAM_URL` point the two
index files elsewhere (the screenshot harness uses a local
`../distfiles/manifest.json` and `tests/fixtures/upstream.json`).

## Layout and boundaries

| Layer | Holds | May import |
| --- | --- | --- |
| `src/domain` | `options.ts` (everything the wizard asks + defaults), `plan.ts` (options → the list of files: `buildPlan`, `renderTemplate`), `configs.ts` (preset.cfg, KTX port/pwd, qtv.cfg, qwfwd.cfg, client launcher, start/stop scripts), `manifest.ts` / `upstream.ts` (index shapes + parsers), `install-state.ts` (`nquake-reborn.json`, `canReuse`), `paths.ts` (names a browser cannot create), `readme.ts` (`README-nquake.txt`), `format.ts`, `progress.ts`, `platform.ts` | nothing outside domain |
| `src/net` | `sources.ts` (URLs, index loading, env overrides), `transport.ts` (fetch + retry/backoff; 404 is final), `installer.ts` (`runInstall`: worker pool, progress, failures collected, record + readme + chmod at the end) | domain, platform types |
| `src/platform` | `capabilities.ts` (which surface; real or simulated), `destination.ts` (the seam — `canSetExecutable`, `restrictsNames`), `fs-access.ts`, `tauri.ts`, `mock.ts` (mock destination + mock transport) | domain |
| `src/ui` | `primitives.tsx` (Button, Card, Field, Toggle, ChoiceCard, Callout, ProgressBar, KeyValue…), `Stepper.tsx`, `icons.tsx`, `steps/*Step.tsx` | domain, app types |
| `src/app` | `wizard.ts` (state, flow, catalog loading, install run), `App.tsx` (shell, mode switch, nav), `main.tsx`, `theme.ts` | everything |
| `tests/` | vitest suites mirroring `src/`; `tests/fixtures/upstream.json` | |
| `scripts/` | `screenshots.mjs`, `mirror-upstream.mjs`, `release/*` (changeset + changelog tooling, copied from the notes app) | |
| `tauri/` | The desktop shell (see below) | nothing from `src/` |

`src/domain/` is pure and eslint enforces it (no DOM, no `fetch`, no
imports from the layers above). **Put every decision there**: which files a
choice adds, where they go, what a config says, what counts as "unchanged".
The UI edits `InstallOptions`; the installer walks the `InstallPlan`; neither
re-derives anything. Later plan items replace earlier ones with the same
destination — that is how an upstream `mvdsv` wins over the bundled one.

### How the plan maps distfiles packages

- Always: `qsw106/ID1/PAK0.PAK` → `id1/pak0.pak` (nothing else from that
  package). With a user `pak1.pak`: `id1/pak1.pak`, and `gpl/id1/gpl_maps.pk3`
  + `gpl/id1/readme.txt` are dropped.
- Client: `gpl` (skip `ezquake.exe` unless Windows *and* using the bundled
  client), `non-gpl` (skip `ezquake/sb/wget.exe` off Windows), `textures`
  (default on), `addon-textures` / `addon-fortress` / `addon-clanarena`
  (opt), `linux` (cfg only, never the tarball), `macosx` (cfg; the old
  `.app` only as fallback), upstream ezQuake for the platform, generated
  `ezquake/configs/preset.cfg`, and on Linux/macOS a generated
  `start_ezquake.sh` (chmods the AppImage / the `.app` binaries, clears
  macOS's quarantine flag, then launches).
- Server: `sv-gpl` (minus `addons/*.sh`), `sv-non-gpl`, `sv-configs`,
  `sv-maps-gpl`, `sv-maps` (default on, 610 MB), `sv-bin-x64` or
  `sv-bin-win32`, upstream MVDSV + KTX replacing `mvdsv[.exe]` and
  `ktx/qwprogs.*`, `sv-ffa` / `sv-ca` / `sv-fortress` (opt; their `.cfg`
  files get `NQUAKESV_*` placeholders substituted), generated
  `ktx/portN.cfg` (the `port_template.cfg` text + per-port lines),
  `ktx/pwd.cfg`, `qtv/qtv.cfg` (template + `qtv 127.0.0.1:<port>` per
  game server), `qwfwd/qwfwd.cfg`, `start_servers.{bat,sh}`,
  `stop_servers.{bat,sh}`, `run/*.sh` restart loops on Unix.
- Ports: N KTX ports from `basePort` (27500), then one port each for FFA, CA,
  TF in that order; QTV TCP 28000; QWFWD UDP 30000.
- After the run: `nquake-reborn.json` (what was installed, hashes, options
  with passwords blanked) and `README-nquake.txt`; executable bits are set
  where the surface can (Tauri) — on the web every generated script chmods
  itself and what it launches, so the Done step / readme say `sh
  start_ezquake.sh` / `sh start_servers.sh` for the first run there and
  `./…` where the bits were set.
- **Names a browser cannot create.** Chromium's File System Access API
  refuses `.lnk`, `.scf` and `.url` outright (and CLSID extensions, trailing
  dots, Windows device names) whatever the OS underneath — nQuake ships
  `ezquake/Online Manual.url`. `domain/paths.ts#browserBlockReason` holds the
  rule, `Destination.restrictsNames` says whether the surface has it, and
  `runInstall` drops those items before the run and reports them as
  `result.blocked` notes rather than failures. Spaces in a name are fine.

Renaming a package or one of the explicitly named paths in distfiles breaks
this; change both in the same breath.

## The wizard

Steps are computed from the options **and the mode** (`stepsFor` in
`app/wizard.ts`).

- **Simple** (default) is Next, Next, Next on the QuakeWorld standard
  setup: welcome → target (Play / Host / Both, platform, optional nickname)
  → folder → review → install → done. Defaults live in
  `domain/options.ts#defaultOptions`: latest ezQuake, 24-bit textures on,
  no HD textures / TF / CA, nickname `player`, WASD; server: two KTX ports
  from 27500, QTV + QWFWD on, latest MVDSV + KTX, full map pack, generated
  rcon / QTV passwords. **A Simple install must never need the Advanced
  steps to be playable.**
- **Advanced** unfolds client → config (keys, mouse, custom binds, preset
  preview) and/or server (identity, ports, passwords, services, binaries,
  content) between target and folder. The switch sits in the card header;
  switching to Advanced from folder/review jumps back to the first unlocked
  step; the Review step offers the jump too.

Each step is a component taking `ctx: WizardCtx`. Navigation lives in
`App.tsx` (desktop: the card footer; phones: a sticky bar under the card).
`canProceed` gates Next per step.

### Simulation mode

`platform/capabilities.ts` decides. Phones and tablets ("QuakeWorld doesn't
run here"), browsers without `showDirectoryPicker` (Firefox, Safari),
non-HTTPS pages and `?mock=1` all get the full wizard with a simulated folder
and simulated downloads (`platform/mock.ts` streams zeroed bytes at a
believable rate, capped so a 600 MB pretend install ends in ~25 s), and say
so in a banner on the welcome, folder, install and done steps. Keep the mock
path identical to the real one apart from `Destination` and `Transport`.

## The desktop shell is thin

`tauri/` embeds `dist/` (built with `npm run build:tauri` → relative base,
single chunk) and holds only what a webview can't do: pick a folder, write
in it, reveal it — three official plugins (`dialog`, `fs`, `opener`),
scoped in `tauri/src-tauri/capabilities/default.json` — and **one** Rust
command, `set_executable`, because a webview cannot chmod. `src/platform/tauri.ts`
is the other side. It imports nothing from `src/`. Anything else a desktop
feature seems to need goes in `src/` behind the destination seam; wanting a
second Rust file is the signal to stop and re-ask. Touch `tauri/` → re-read
`tauri/README.md`. CI runs `cargo check` + `cargo fmt --check` on it
(`tauri-check`); a full bundle is only built by the Release workflow. Icons
under `tauri/src-tauri/icons/` are generated from `public/favicon.svg` with
`npm --prefix tauri run icons` (drop the `android/` and `ios/` sets it also
emits).

## Screenshots

`scripts/screenshots.mjs` builds, serves `dist/`, drives the wizard through
its `data-testid` hooks with `?mock=1`, and writes
`screenshots/<scenario>/<viewport>-<theme>/<nn>-<step>.png` for
`simple` / `client` / `server` / `both` (the last three switch to Advanced
on the target step) at desktop 1440×900 and phone 390×844, dark and light.
Run it after any visible change and **look at the PNGs** (the Read tool
renders them). Keep the test ids it clicks: `nav-next`, `mode-*`,
`target-*`, `platform-*`, `nickname`, `opt-*`, `hostname`, `pick-folder`,
`install-percent`, `done`, `catalog-ready`. It sets `data-shot` on `<html>`
so the phone nav renders in flow (see `theme.css`). Playwright is resolved
from a global install, not a project dependency; `--url` points it at a
running dev server, `--scenario/--viewport/--theme/--platform` narrow a run.

## Design

Familiar to nquake.com: charcoal linen background (drawn in CSS), the
"nQuake" wordmark with an orange *n* and silver *Quake* in Open Sans
Condensed, the Playball slogan "QuakeWorld — where it all started", yellow
links, an orange primary button. Both faces are self-hosted via
`@fontsource`. Tokens live in `src/styles/theme.css` (dark default, light
variant, `<html data-theme>`, OS preference + a header toggle remembered in
`localStorage`); use the slot names (`bg-surface`, `text-muted`,
`border-line`, `text-accent`…), never raw colours in components. Desktop
shows a sidebar stepper; phones get a compact strip and a sticky bottom nav.
**Both viewports are primary**; check every visible change at both.

## Deploy, release, changelog

Modelled on the notes app.

- `ci.yml`: fmt-check, lint (eslint + tsc), test, build; `tauri-check`; and
  `changeset`, which requires a fragment under `.changes/unreleased/` for
  user-visible changes (skip-list in `scripts/release/check-changeset.mjs`,
  or the `no-changelog` label).
- `pages.yml` (push to `main`, `workflow_dispatch`, `workflow_call`):
  assembles the root slot (highest `v*` tag; `main` until the first release),
  `/preview/` (`main`) and an opt-in `/branch/` (parked on the orphan
  `branch-deploy` branch) into one artifact. The base path is
  `/<repo-name>/` on `*.github.io` (so `/nquake-reborn/`) or `/` when the
  `PAGES_CNAME` secret is set; `vite.config.ts` reads it from `VITE_BASE`.
  The org-level custom domain makes the site https://nquake.com/nquake-reborn/
  without any secret. `dist/404.html` is a copy of `index.html`.
- `release.yml` (manual): bump from the fragments' front-matter
  (`compute-bump.mjs`, `breaking: true` → major, Added/Changed → minor,
  Fixed → patch), collate `CHANGELOG.md`, bump `package.json`, tag `vX.Y.Z`,
  create a **draft** release, build Tauri bundles for Windows x64, macOS
  arm64 + x64 and Linux x64 with `tauri-apps/tauri-action` and attach them,
  publish, and chain into `pages.yml`. Signing secrets are optional
  (`APPLE_*`); unsigned builds get the Gatekeeper / SmartScreen note in the
  release body.
- `mirror-upstream.yml`: see above. Skips the push when nothing changed.
- Dependabot watches npm (root and `tauri/`), cargo and actions weekly.

Conventional Commits; PRs squash-merge, so the PR title is the commit.
`BUILD_LABEL` (`<version>.<run>[-pre|-br]`) shows in the footer and
`version.json`.

## State of things / known follow-ups

- **Verified:** unit tests, build, `cargo check`, the full screenshot
  matrix, and — after merge — the live site loading the distfiles catalog
  and the upstream mirror through CORS in a real Chromium session.
- **Not yet exercised end to end:** a real install into a folder in Chrome
  or Edge, a real install through the Tauri app, and the Release workflow's
  desktop bundles. Treat the first bug report from any of those as expected.
- Firefox and Safari have no folder access, so they only get the
  simulation; a "download as zip" fallback (streaming a zip to the browser)
  is the obvious next surface behind the same seam.
- No uninstaller yet; `nquake-reborn.json` records what was written so one
  can be built without guessing.
- English only; no i18n runtime. No service worker on purpose (an installer
  gains nothing from offline, and stale caches would bite).
- The catalog and mirror are fetched with `cache: "no-cache"`; raw's CDN
  still caches for up to five minutes.
